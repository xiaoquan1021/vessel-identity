# 动机：公开血管模型里的身份与绑定是怎么表达的

本文记录一次对公开数据的实测审计，说明本库要解决的问题在真实项目文件里长什么样。审计对象与方法可复现；数据本身不随本仓库分发。

## 审计对象

- 来源：[Vascular Model Repository](https://www.vascularmodel.com)（VMR），SimVascular 项目包，直链下载无需注册。
- 样本：按疾病分组抽取的 20 个主动脉病例（健康、主动脉缩窄、腹主动脉瘤、主动脉夹层各 5 例），2026-10-11 下载。
- 方法：直接读取 zip 内的 SimVascular 项目文件（`.pth` 中心线、`.mdl` 模型面、`.sjb` 仿真作业、`svpre`、`solver.inp`、`rcrt.dat`），不运行求解器。

## 发现一：边界条件靠"位置"绑定到出口

出口的 RCR 参数从声明到求解器输入要经过三跳，每一跳都按位置而不是按身份：

```
.sjb        <cap name="btrunk"> ... Values="324.0 0.00013963 8942.0"      按名字
svpre       set_surface_id_vtp .../btrunk.vtp 3                            面编号由行序决定
solver.inp  List of RCR Surfaces: 3 4 5 6 7                                按列表位置
rcrt.dat    2 / 324.0 / 0.00013963 / 8942.0 / ...                           按块顺序，不含任何名字
```

在 15 个带仿真作业的样本中，15 个的 `rcrt.dat` 都不含名字，绑定完全依赖顺序。15 个此刻都是自洽的——但没有任何结构保证下一次编辑之后仍然自洽。若新增一个出口、重新导出网格面或手工调整文件，RCR 会静默绑到另一支血管上，求解照常运行。

本库的对应做法：出口属于某个 `EntityId`，绑定按实体而不是按顺序查找；几何修订之后用谱系回答"这条血管还是不是原来那条"。

## 发现二：状态字段不携带信息

15 个仿真作业的自报状态全部是 `status="Simulation failed"`，而同一仓库的目录把这些病例标为"有仿真"。一个取值永远相同的状态字段等于没有状态。

这不意味着这些仿真都失败了；它意味着"求解器正常结束"、"数值收敛"、"结果可信"三件事在上游元数据里无法区分。本库的 `invalidate()` 因此不读取任何自报状态，只依据谱系边与几何比对。

## 发现三：身份是名字

中心线文件 `btrunk.pth`、模型面 `btrunk`、网格面 `btrunk.vtp` 之间唯一的关联是名字相同。按角色命名的面（`inflow`、`outflow`）没有同名中心线，15/20 的样本都有这种情况。

把名字当身份，意味着重命名就是换了一个实体，而真正换了一条血管却可能沿用旧名字。本库的 `EntityId` 不编码任何语义，正是为了切断这种耦合。

## 其他观察

- 20/20 个样本没有任何显式的单位字段（全部依赖 cgs 约定）。
- 15/15 个仿真作业的出口压力写作 `0.0`，没有参考点说明（表压？绝对压？远端参考？）。
- 15/15 个仿真作业的全局残差容差为 `1.0e12`。

## 复现

审计脚本与样本清单（病例名、URL、本地 sha256）见使用本库的平台仓库；任何人可以从 VMR 直接下载同样的病例复现上述统计。
